## 문항

### Q921. MAVLink v1의 주요 보안 취약점은?
- ✅ 패킷에 인증 및 암호화가 없어 누구나 가짜 명령을 전송하거나 통신을 도청 가능
-    해킹하려면 전문 장비가 반드시 필요
-    MAVLink v1은 AES-256 암호화를 지원
-    패킷 손실이 발생하는 물리 계층 취약점

**해설**: MAVLink v1은 헤더, 페이로드, CRC만 포함하며 인증(서명)과 암호화가 없습니다. SDR(소프트웨어 정의 라디오)로 신호를 수신하고 pymavlink 라이브러리로 쉽게 디코딩·조작이 가능합니다.

**팁**: MAVLink v2는 Message Signing(CRC-SHA256 기반)을 추가했으나 암호화는 여전히 상위 계층에 위임합니다.

### Q922. 드론 GCS 소프트웨어의 'SQL Injection' 취약점이 발생하는 상황은?
- ✅ 사용자 입력(임무 이름, 웨이포인트 설명)을 검증 없이 SQL 쿼리에 직접 삽입하여 DB 조작 가능
-    SQL Injection은 드론 하드웨어에만 발생
-    GCS가 인터넷에 연결되지 않으면 안전
-    암호화된 통신 채널에서는 발생 불가

**해설**: GCS 소프트웨어(QGroundControl, Mission Planner 등)가 임무 저장 시 사용자 입력을 SQLite DB에 저장합니다. 입력 검증 없이 SQL 문자열에 삽입하면 '; DROP TABLE missions;-- 같은 공격으로 DB 삭제 또는 데이터 유출이 가능합니다.

**팁**: Prepared Statement(파라미터화 쿼리)로 SQL Injection을 원천 차단합니다.

### Q923. 드론 펌웨어 업데이트 보안에서 '코드 서명(Code Signing)'이 필요한 이유는?
- ✅ 펌웨어 출처와 무결성을 검증하여 악성 펌웨어 설치를 방지
-    업데이트 속도를 높이기 위해
-    펌웨어 파일 크기를 줄이기 위해
-    배터리 소모를 최소화하기 위해

**해설**: 코드 서명은 제조사의 개인 키로 펌웨어에 디지털 서명하고, 드론 부트로더가 공개 키로 서명을 검증합니다. 서명이 유효하지 않은 펌웨어는 설치를 거부하여 악성 코드 삽입을 방지합니다.

**팁**: PX4와 ArduPilot은 아직 완전한 코드 서명 체계를 갖추지 않아 공식 배포 외 펌웨어 설치 위험이 있습니다.

### Q924. 드론의 'RF 하이재킹(RF Hijacking)' 공격이란?
- ✅ 공격자가 원래 조종 신호보다 강한 신호를 방사하여 드론이 공격자 명령을 수신하게 하는 신호 재밍+스푸핑 조합
-    드론 배터리를 방전시키는 공격
-    드론 카메라 영상을 도청하는 행위
-    드론 GPS 수신기를 물리적으로 파괴

**해설**: RF 하이재킹은 정품 RC 신호를 재밍하여 차단한 후, 더 강한 위조 RC 신호로 드론을 제어합니다. 암호화·인증이 없는 RC 프로토콜(DSM2, PPM 등)에서 가능하며 드론을 완전히 탈취합니다.

**팁**: FHSS와 AES 암호화를 지원하는 RC 링크(TBS Crossfire, ELRS Secure Mode)로 하이재킹을 방지합니다.

### Q925. 드론 보안에서 '최소 권한 원칙(Principle of Least Privilege)'을 적용하는 예시는?
- ✅ GCS 운용사는 임무 계획 권한만 부여하고, 펌웨어 업데이트 권한은 관리자만 보유
-    모든 사용자에게 모든 기능을 허용
-    보안 강화를 위해 모든 기능을 비활성화
-    인터넷 연결 없이는 모든 권한 부여

**해설**: 최소 권한 원칙은 각 사용자/시스템이 작업에 필요한 최소한의 권한만 갖도록 합니다. GCS에서 일반 운용사는 임무 계획·비행 제어만, 관리자는 시스템 설정·펌웨어 업데이트 권한을 가져 내부 위협과 계정 탈취 피해를 제한합니다.

**팁**: RBAC(Role-Based Access Control)로 역할별 권한 집합을 정의하고 관리합니다.

### Q926. 드론 데이터 보안에서 '전송 계층 보안(TLS/DTLS)'을 MAVLink에 적용하는 이유는?
- ✅ 지상 GCS와 드론 간 모든 MAVLink 패킷을 암호화하여 도청 및 중간자 공격 방지
-    TLS는 웹 브라우저 전용
-    암호화로 전송 지연 제거
-    배터리 효율 향상

**해설**: TLS(TCP 기반) 또는 DTLS(UDP 기반)로 MAVLink 채널을 암호화하면 공격자가 트래픽을 수신해도 내용 해독이 불가합니다. 또한 인증서 기반 상호 인증으로 위조 GCS나 드론의 연결을 차단합니다.

**팁**: MAVLink over WebSocket + TLS 구성이 클라우드 기반 드론 관리 플랫폼에서 표준화되고 있습니다.

### Q927. 드론 사이버 보안에서 '침투 테스트(Penetration Testing)'의 목적은?
- ✅ 실제 공격자 관점에서 취약점을 사전 발견하여 운용 전 보안 패치 적용
-    드론 비행 성능 측정
-    배터리 수명 평가
-    펌웨어 코드 품질 검사

**해설**: 침투 테스트(Pentest)는 승인된 보안 전문가가 실제 공격 기법으로 시스템을 공격하여 취약점을 발견합니다. 드론 시스템에서는 RF 인터셉트, GCS 웹 취약점, 펌웨어 리버싱, 물리적 접근 공격 등을 테스트합니다.

**팁**: 드론 보안 표준(NIST SP 800-187, DO-326A)은 정기적 취약점 평가를 요구합니다.

### Q928. MAVLink v2의 'Message Signing' 메커니즘 구조는?
- ✅ 13바이트 서명(링크ID 1B + 타임스탬프 6B + HMAC-SHA256 앞 6B)으로 출처 인증 및 재전송 공격 방지
-    AES-256으로 전체 패킷 암호화
-    공개키 기반 PKI로 디지털 서명
-    MD5 해시로 무결성만 확인

**해설**: MAVLink v2 서명은 13바이트로 구성됩니다. Link ID(1B)는 발신 링크 식별, Timestamp(6B, 250ms 단위)는 재전송 공격 방지, HMAC-SHA256의 처음 48비트(6B)는 공유 비밀 키로 출처 인증을 제공합니다.

**팁**: 서명 검증 실패 시 패킷을 버리거나 경보를 발생시켜야 합니다. ArduPilot/PX4에서 Signing 활성화 설정이 가능합니다.

### Q929. 드론 부트로더의 'Secure Boot' 구현에서 'Root of Trust'의 역할은?
- ✅ 하드웨어 보안 요소(HSM, TrustZone)에 저장된 불변의 공개 키로 첫 번째 부트로더 서명을 검증하여 신뢰 체인 시작
-    드론 부팅 속도를 높이는 하드웨어 기능
-    암호화 키를 생성하는 랜덤 넘버 제너레이터
-    배터리 보호 회로

**해설**: Secure Boot는 신뢰 체인(Chain of Trust)으로 구성됩니다. Root of Trust는 HSM 또는 OTP(One-Time Programmable) 메모리에 저장된 공개 키로, 하드웨어 수준에서 변경 불가합니다. 이 키로 1단계 부트로더 서명을 검증하고, 이후 순차적으로 OS·펌웨어를 검증합니다.

**팁**: ARM TrustZone과 STM32의 RDP(Read-out Protection)가 드론 MCU의 Secure Boot에 활용됩니다.

### Q930. 드론 GCS의 '원격 코드 실행(RCE, Remote Code Execution)' 취약점 발생 예시는?
- ✅ GCS가 수신한 MAVLink STATUSTEXT 메시지를 파싱하여 로그 파일에 쓸 때 경로 트래버설 또는 명령 인젝션 가능
-    RCE는 웹 서버에서만 발생
-    암호화된 통신에서는 RCE 불가능
-    오프라인 GCS는 RCE 면역

**해설**: GCS가 드론으로부터 받은 STATUSTEXT나 MISSION_ITEM 데이터를 충분한 검증 없이 파일 시스템 작업이나 시스템 명령에 사용할 때 RCE가 발생할 수 있습니다. 악성 드론이나 중간자 공격으로 조작된 패킷이 GCS PC에서 임의 코드를 실행합니다.

**팁**: GCS 소프트웨어의 모든 외부 입력 처리 코드는 입력 검증과 샌드박스를 적용해야 합니다.

### Q931. 드론 보안에서 'Side Channel Attack(부채널 공격)'의 예시는?
- ✅ 드론 MCU의 암호화 연산 시 전력 소비 변화 분석(SPA/DPA)으로 개인 키 추출
-    드론 배터리 전압 측정으로 위치 추정
-    RF 신호 분석으로 조종사 신원 파악
-    드론 카메라 영상에서 위치 정보 추출

**해설**: 부채널 공격은 알고리즘 자체가 아닌 구현 측면(전력, 타이밍, 전자기 방사)을 이용합니다. MCU의 AES 연산 시 전력 소비 파형을 분석하는 DPA(Differential Power Analysis)로 AES 키를 추출할 수 있습니다.

**팁**: 부채널 내성을 위해 마스킹(Masking), 하이딩(Hiding) 기법을 적용하거나 전용 보안 MCU(SE050 등)를 사용합니다.

### Q932. 드론 통신의 '재전송 공격(Replay Attack)' 방어 방법은?
- ✅ 타임스탬프(수신 윈도우 5초) + 시퀀스 번호로 이미 처리된 패킷을 캐시하여 중복 수신 패킷 거부
-    더 강한 암호화 알고리즘 사용
-    패킷 크기를 크게 하여 전송 어렵게
-    무선 전력을 낮춰 캡처 범위 제한

**해설**: 재전송 공격은 합법적 패킷을 캡처해 나중에 재전송합니다. 타임스탬프 기반 유효 시간 윈도우(예: ±5초)로 오래된 패킷을 거부하고, 시퀀스 번호로 이미 처리한 패킷을 재사용하지 않습니다. MAVLink v2 서명의 6바이트 타임스탬프가 이 역할을 합니다.

**팁**: 클록 동기화(GPS 기반 UTC)가 정확하지 않으면 타임스탬프 방어가 우회될 수 있습니다.

### Q933. 드론 시스템의 '공급망 공격(Supply Chain Attack)' 위험 사례는?
- ✅ 악성 코드가 삽입된 ESC 펌웨어, GPS 모듈, 카메라 소프트웨어가 정상 제품으로 납품되어 운용 중 활성화
-    드론 구매 후 외부 공격자가 직접 수정
-    인터넷 연결 드론에서만 발생
-    공급망 공격은 소프트웨어에만 해당

**해설**: 공급망 공격은 제조·유통 단계에서 하드웨어나 소프트웨어에 악성 코드를 삽입합니다. DJI 드론의 정보 유출 우려, 중국산 부품의 백도어 가능성이 미국 정부 조달 금지 조치의 배경입니다.

**팁**: NDAA(국방수권법) Section 848은 특정 중국 드론 제조사 제품의 미군 조달을 금지합니다.

### Q934. 드론 PX4 비행 컨트롤러의 'Trusted Execution Environment(TEE)'에서 보안 파라미터를 격리하는 방법은?
- ✅ ARM TrustZone으로 일반 영역(Normal World)과 보안 영역(Secure World)을 하드웨어 분리하여 암호화 키·서명을 보안 영역에서만 처리
-    PX4 부트로더가 시동 시 펌웨어 서명을 RSA-2048로 검증하고 서명이 유효하지 않으면 부팅을 거부하여 변조된 펌웨어 실행을 원천 차단하는 방식
-    OP-TEE 보안 OS가 키 스토리지와 암호화 연산을 전담하고 Linux/NuttX 영역의 코드는 키 값을 직접 접근할 수 없으며 TA(Trusted App) API로만 호출
-    PX4 ROMFS에 암호화된 파라미터 블록을 저장하고 부팅 시 하드웨어 고유 UID를 키로 복호화하여 기체 고유 보안 설정을 플래시 외부 노출 없이 적용

**해설**: ARM TrustZone은 프로세서를 Normal World(리치 OS, 비행 SW)와 Secure World(신뢰 애플리케이션, TEE OS)로 하드웨어 격리합니다. 암호화 키, 서명 연산, 부팅 검증이 Secure World에서 수행되며 Normal World의 침해가 발생해도 보안 자산이 보호됩니다.

**팁**: OP-TEE는 오픈소스 TEE 구현으로 ARM 기반 드론 컴패니언 컴퓨터(Jetson, RPI)에 적용 가능합니다.

### Q935. 드론 시스템의 '취약점 공개 정책(CVD, Coordinated Vulnerability Disclosure)'이 중요한 이유는?
- ✅ 연구자가 발견한 취약점을 제조사에 먼저 알려 패치 개발 기간(보통 90일)을 주고, 이후 공개하여 사용자 보호와 보안 연구 장려를 균형
-    발견 즉시 공개하는 것이 최선
-    취약점은 절대 공개하면 안 됨
-    제조사가 취약점을 영구 비공개할 권리 있음

**해설**: CVD는 보안 연구자, 제조사, 사용자 모두를 보호합니다. 즉각 공개(Full Disclosure)는 패치 전 공격자가 악용하고, 영구 비공개는 취약점이 방치됩니다. 90일 표준 기간 후 공개가 패치와 공개 균형의 표준입니다.

**팁**: DJI Bug Bounty 프로그램과 PX4 Security Advisory가 드론 CVD의 사례입니다.

### Q936. 드론 펌웨어 리버스 엔지니어링에서 'CFG(Control Flow Graph) 분석'이 취약점 발견에 활용되는 방법은?

### Q937. 드론 네트워크의 'Zero Trust Architecture(제로 트러스트)' 원칙을 드론 C2에 적용하는 방법은?

-    VPN 연결 시 자동으로 Zero Trust 달성
