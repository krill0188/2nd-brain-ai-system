## 개별 기술 분석

### 1. LangGraph — **보류**
- **해결 문제**: 다중 에이전트의 그래프형 오케스트레이션(분기·병렬·체크포인트).
- **필요한가**: 아니오. 목표 루프는 선형 순차(①→⑧)이며 분기는 승인 게이트뿐. bash 상태 머신 + state.json으로 충분하고 재현·디버깅이 더 쉽다.
- **중복**: research-run.sh Orchestrator와 정면 중복.
- **로컬**: 가능(Python). **Vercel**: 무관(연구는 로컬 전용).
- **비용**: OSS 무료. 단, Python 의존성 트리 + 학습 곡선이라는 숨은 비용.
- **시기**: 병렬 다중 모델 연구(예: 두 모델 교차 검증)가 실제 요구될 때 재검토.

### 2. Hermes Agent — **채택 (이미 운영 중)**
- **해결 문제**: cron 스케줄링 + 텔레그램 전달 + 스킬 실행. 새벽 체인 6잡의 검증된 기반.
- **필요한가**: 예 — Phase 3 승인 게이트의 전달 채널로 재사용. 신규 도입 아닌 활용 확대.
- **중복**: 없음. **비용**: 기존 그대로(추가 0).
- **유의**: deliver는 단방향 발송임을 실측 확인. 양방향 승인은 Phase 3에서 Hermes Agent 대화 방식 vs AI Fleet HITL 승인게이트(기 구축) 재사용 중 검증 후 선택.

### 3. LiteLLM — **제외**
- **해결 문제**: 멀티 프로바이더 통합 프록시 + 비용 추적.
- **필요한가**: 아니오. **OpenRouter가 이미 동일 역할**(단일 API로 멀티 모델 + 단일 과금 지점) 수행 중. 로컬 추론은 claude CLI 구독으로 라우팅 자체가 불필요.
- **중복**: OpenRouter와 정면 중복. **비용**: 무료 OSS지만 상주 프록시 프로세스 = 듀얼코어에서 순수 손해.

### 4. Qdrant — **제외**
- **해결 문제**: 대규모 벡터 검색 서버(HNSW, 필터링).
- **필요한가**: 아니오. 120편(청킹해도 ~1,500청크)은 브루트포스 내적으로 밀리초 단위 — 인덱스 서버가 해결할 문제가 존재하지 않음.
- **로컬**: Docker 상주 필요 — 2코어/16GB에 상시 부담. **Vercel**: 자체 실행 불가, 외부 호스팅 유료.
- **비용**: Cloud 유료 또는 로컬 자원 비용.

### 5. LanceDB — **보류 (벡터 저장 1순위 후보)**
- **해결 문제**: 서버 없는 임베디드 파일형 벡터 DB.
- **필요한가**: 아직 아니오. Phase 2의 `.ua/embeddings.json` + 브루트포스가 현 규모에서 동등 성능·더 단순. JSON 방식은 sync-wiki.sh로 Vercel까지 그대로 운반된다는 결정적 장점.
- **중복**: embeddings.json과 중복. **로컬**: 우수(임베디드). **Vercel**: 번들 포함 가능하나 복잡.
- **재검토 트리거**: canonical 1,000편↑ 또는 브루트포스 검색 300ms↑.

### 6. Chroma — **제외**
- LanceDB와 동일 범주에서 이점 없음(Python 서버 지향, Node/Vercel 통합 약함). 벡터 DB가 필요해지는 시점에도 LanceDB가 우선.

### 7. Neo4j — **제외**
- **해결 문제**: 대규모 그래프 저장 + Cypher 질의 + 그래프 알고리즘.
- **필요한가**: 아니오. 137노드/421엣지는 JSON 파일 + 인메모리 순회로 충분. JVM 상주는 16GB 램에서 웹·claude 세션과 경합.
- **Vercel**: 자체 실행 불가(Aura 유료).

### 8. KuzuDB — **보류 (그래프 확장 1순위 후보)**
- **해결 문제**: 임베디드 그래프 DB(서버 없음) + Cypher — Neo4j의 경량 대안.
- **필요한가**: 아직 아니오. Phase 2의 JSON 엣지 스키마 확장(type/evidence/confidence/status)으로 요구 충족.
- **재검토 트리거**: 엣지 5,000↑, 또는 다중홉 경로 질의("A와 C를 잇는 모순 경로")가 연구 루프의 병목이 될 때.

### 9. BGE-M3 → **multilingual-mpnet로 교체 (Phase 2, 사전계산 전용, 2026-08-01 실사용 검증 후 확정)**
> ⚠️ 최초 이 표는 "BGE-M3 채택"이라고 적었으나, Phase 2 착수 시 실제
> 확인해보니 채택 라이브러리(`fastembed`)의 내장 모델 30종에 BGE-M3
> 자체가 없었다(라이브러리 실사용 가능 여부를 사전 확인하지 않은 채 이름만
> 적은 것 — 착오였다). 대체로
> `sentence-transformers/paraphrase-multilingual-mpnet-base-v2`
> (1.0GB, 768차원, ~50개 언어)를 실측 검증 후 채택했다.
- **해결 문제**: 한/영/다국어 의미 임베딩 — 현 시스템 최대 결핍(교차 언어 검색 실패)을 직접 해결.
- **실측 검증(2026-08-01)**: 한글 질의 "군집 비행의 GPS 차단 환경 항법" ↔ 영문 문서 코사인 유사도 0.776, 무관 주제 대비 0.529 — 교차언어 매칭이 실제로 작동함을 확인. `research-search.py`/`lib/rag.ts`에 실제 배선 후 "위치 인식 불가 상황에서 스스로 길을 찾는 기술"(영단어 0개) 질의로 `decentralized-swarm-gps-denied` 등 관련 문서를 정상 검색 — 기존 키워드 방식이면 매칭 0건이었을 사례.
- **로컬 실행**: Python 3.14(시스템)는 onnxruntime 휠 미지원 확인됨 → Python 3.11 격리 venv(`~/2nd/.venv`, gitignore 대상) 별도 구성. 문서 465건(canonical+raw+news) 임베딩 생성 405초(1회, 캐시된 모델 로드는 5초) — 듀얼코어에서도 배치 작업으로는 무리 없음.
- **Vercel**: 모델 배포 불필요 — 사전계산 벡터 JSON(`​.ua/embeddings.json`, 3.65MB/465건)만 스냅샷 포함. 질의측 임베딩은 `.venv` 존재 여부로 자동 분기 — 로컬 dev는 동일 모델 subprocess 호출, Vercel(.venv 미배포)은 자동으로 키워드 전용 폴백. OpenRouter 임베딩 API 연동은 **검증 없이 도입하지 않고 보류**(엔드포인트 미검증 상태로 프로덕션에 넣지 않는다는 원칙 적용).
- **비용**: 모델 무료, 전기료 수준. 신규 유료 API 호출 0건(폴백 방식 채택으로 회피).

### 10. reranker (bge-reranker 등) — **보류**
- **해결 문제**: 1차 검색 상위 후보 재정렬로 정밀도 향상.
- **필요한가**: 아니오. 후보 풀 자체가 작아(120편) 하이브리드 점수만으로 top-5 품질 확보 가능. cross-encoder는 CPU에서 질의당 수 초 — 실시간 Q&A에 부적합.
- **재검토 트리거**: 500편↑ + top-5 정밀도 불만이 실측될 때. 도입 시에도 로컬 연구 루프 한정(Vercel 제외).

### 11. OpenRouter — **채택 (유지)**
- **해결 문제**: Vercel(claude CLI 부재) 환경의 LLM 호출 + 모델 교체 유연성 + 단일 과금.
- 이미 웹 Q&A(claude-haiku-4.5)와 gate-c 폴백에서 사용 중. **비용 통제 지점으로 공식화**: 종량 호출은 전부 OpenRouter 경유 → 대시보드 한 곳에서 총비용 관측.
- **모델 라우팅 정책**: 웹 Q&A=haiku(저가) / 연구 루프=claude CLI 구독(비용 0) / 임베딩 폴백=소액 API. LiteLLM 없이 이 3줄 정책으로 통제 완료.

### 12. Claude Code — **채택 (연구 루프 실행 엔진)**
- **해결 문제**: 연구 루프의 모든 LLM 역할(⑦역할 순차 수행). Max 구독이므로 **한계비용 0** — "유료 AI 다중 호출 금지" 제약을 구조적으로 충족.
- **로컬**: 운영 중. **Vercel**: 불가 — 의도된 분리(연구=로컬).
- **유의**: PRO/Max 한도(과거 429 이력) → 세션당 호출 ≤10회 제한 + 연구는 수동 트리거(야간 자동 연구 금지)로 한도 보호.

### 13. Codex — **유지 (역할 불변)**
- 현행 역할(코드 구현·버그 수정, AGENTS.md Tool Roles 표)을 유지. 연구 루프에는 불투입 — 지식 추론은 Claude 단일 모델로 일관성 확보. Phase 1~5 구현 작업 시 코드 작성 도구로는 활용 가능.
