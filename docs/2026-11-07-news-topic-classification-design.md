# 뉴스 주제 분류 개선 설계 (2026-11-07)

상태: **구현 완료(v3.10.0, 2026-11-07)** — ① `scripts/news_topics.py` · ② `scripts/fetch-topic-sources.py`+`news-topic-sources.json`(24개 소스) · 웹 ③(필터·건수·빈 메뉴 흐림·PKM 제외, 웹 v2.21.3).

### 구현 결과(실측)
- 골든셋 55건(`scripts/fixtures/news-topics-golden.json`, 직접 라벨링) 일치율 **84%**(2회 동일), 닫힌 목록 위반 0. 평가: `python3 scripts/eval-news-topics.py`.
- 합격선 정정: "빈 라벨 ≤ 25%" 는 이 피드에 맞지 않았다. 골든셋의 47% 가 리뷰·완구·행사처럼 주제 없는 기사라 빈 예측 45% 가 정상이다 → 기준은 일치율 ≥ 80% + 닫힌 목록 위반 0 으로 한다.
- 기존 500건 백필 후 비어 있던 13개 메뉴가 모두 채워졌다(최소 ROS·미들웨어 4건, 기계·구조 7건). 신규 소스 24개 모두 수집 성공.
- 한계: 주제 정밀도는 약 80~85% 수준(예: 강의 영상이 엣지 AI 로 분류되는 오분류가 일부 있음). ROS·기계·엣지 AI 처럼 소스가 적은 주제는 건수가 적다.

## 1. 문제

웹 `/news` 의 주제 메뉴 20개(`lib/types.ts` `DOMAIN_META`) 중 14개가 비어 있다.

| 확인 | 결과 |
|---|---|
| 뉴스 피드 500건의 `domain` | 옛 7종뿐: `hardware` 260, `ops-mission` 124, `ai-autonomy` 34, `gcs-software` 28, `flight-control` 25, `comms-protocol` 13, `regulations` 13 |
| 분류 시점 | 수집기(`fetch-inbox.sh` 3곳, `fetch-law.py`)가 소스별 고정값으로 붙여 `news-feed-append.py` 에 넘긴다. `news-feed-append.py` 는 병합만 한다 → **새 분류를 판정하는 코드가 없다** |
| 키워드 규칙 시험(500건) | 새 분류로 읽힌 것이 301건이지만 제조사 197건은 제조사명 언급만으로 잡혀 부정확하고(예: IEEE *Spectrum* → RF), 나머지 12개 메뉴는 1~21건. **분류를 완벽히 해도 수집 자체가 해당 주제를 거의 다루지 않는다** |

두 문제는 따로 풀어야 한다: ① 분류 부재, ② 수집 범위 부족.

## 2. 설계

### ① 분류: 추가형(additive) 다중 라벨

- `domain`(옛 7종)은 **그대로 둔다.** 위키 페이지·품질 게이트·기존 소비자가 쓰기 때문에 바꾸면 깨진다.
- 항목에 `topics: [최대 2개]` 를 **추가**한다. 값은 새 13종 중에서만(닫힌 목록).
- 웹 필터: `it.domain === domain || it.topics?.includes(domain)`.
- 분류기: `news-feed-append.py` 안에서 **새로 들어오는 항목만** 배치(20건/호출)로 LLM에 묻는다.
  - 라우터 확정 순서(`claude -p` → NIM 무료 → OpenRouter 무료)를 쓴다.
  - 출력은 JSON 한 줄 `{"<url해시>": ["security"], ...}`. 닫힌 목록 밖의 값은 버린다.
  - 확신 없으면 빈 배열 `[]`(억지로 채우지 않는다. 제품 설계 게이트의 "무조건 생성 금지" 원칙과 같다).
  - **fail-open**: 분류가 실패해도 항목 병합은 막지 않는다. `topics` 가 없는 항목은 다음 실행에서 다시 시도한다(`topics_tried` 횟수 상한 3).
- 기존 500건은 1회 백필(25회 호출 안팎).
- 제조사(`vendor-registry`)는 "제조사 이름이 나온 기사"가 아니라 "제조사 신제품·공시·인수 소식"으로 정의를 좁힌다(프롬프트에 명시).

#### 검증
- 골든셋 60건(주제별 4~5건)을 직접 라벨링해 일치율·빈 라벨 비율·닫힌 목록 위반 0건을 측정한다.
- 합격선: 일치율 ≥ 80%, 빈 라벨 ≤ 25%, 닫힌 목록 위반 0.
- 단위 테스트: 닫힌 목록 필터, fail-open, 재시도 상한, 멱등(같은 입력 → 같은 파일).

### ② 수집 보강(소스 목록은 별도 승인)

비어 있는 주제를 채우려면 소스를 추가해야 한다. 후보(실제 수집 전 접근성·약관 확인 필요):

### ③ 화면

- 항목이 0건인 메뉴는 `0` 배지를 보이고 흐리게 처리하거나 접는다. 눌러서 빈 화면을 만나지 않게 한다.
- 메뉴 옆에 건수를 표시한다(발행마다 갱신).
- 이 변경은 웹 코드(`app/news/page.tsx`)만 건드린다.
