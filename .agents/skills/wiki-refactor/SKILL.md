# Wiki Refactor

핵심 원칙: **새 문서를 만드는 것보다, 기존 지식을 최신 근거로 바꾸는 것이 우선**이다.

## 입력
- 오늘(마커 파일 mtime 이후) 새로 생긴/수정된 `raw/`와 canonical 페이지 (러너가 목록을 프롬프트에 제공)

## 절차
1. 오늘 새 근거 각각에 대해 관련 기존 canonical 페이지를 찾는다(태그·제목·wikilink·`scripts/research-search.py`)
2. 페이지별로 다음만 수행:
   - **강화**: 새 근거가 기존 주장을 지지 → 문장 끝에 `^[raw/...]` 추가, 필요 시 `confidence` 상향
   - **약화/모순**: 상충 → 덮어쓰지 말고 `contested: true`, `contradictions:`에 양쪽 출처 기록, 본문에 "상충" 절 추가
   - **연결**: 관련 페이지 간 `[[wikilink]]` 보강(존재하는 페이지만)
   - **갱신**: `updated:` 날짜, 방법/주제 페이지의 최신 결과 표 갱신
3. 갱신된 페이지마다 log.md에 한 줄 추가(index.md는 페이지가 새로 생긴 경우만)

## 제한 (러너가 강제)
- 한 실행에서 **최대 15개 페이지**만 수정. 초과 후보는 건드리지 말고 다음 실행 몫으로 남긴다
- `raw/` 수정 금지, 페이지 삭제·이름 변경 금지, 새 페이지 생성은 SCHEMA.md threshold 충족 시에만
- 근거 없는 주장 추가 금지 — 모든 신규 문장은 실제 존재하는 raw 경로를 인용

## 검증
- `python3 scripts/lint-knowledge.py --full` 실패 시 러너가 백업으로 자동 롤백한다 — 그러니 lint 규칙(필수 frontmatter, 링크 유효성, 태그 등록)을 지켜라

## 출력
- 마지막 줄: "리팩터링 N개(강화 a / 약화 b / 링크 c), 스킵 N개"
