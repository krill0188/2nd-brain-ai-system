# Novel Combination 후보

## 후보 1
- idea: PID 게인(P/I/D 값과 그로 인한 감쇠·오버슈트 특성)을 단순한 내부 제어 파라미터가 아니라, 드론이 주변 공역의 다른 드론·유인기·관제 시스템에게 "나는 지금 얼마나 예측 가능하게 움직일 것인가"를 알리는 일종의 비언어적 신호(디지털 보디랭귀지)로 재정의한다. LLM 기반 미션 협상 에이전트가 임무 맥락(인구밀도, 기상, 긴급도, 규제 변화)을 실시간으로 해석해 게인 세팅을 조정하고, 그 조정된 게인 프로파일 자체를 BVLOS 트래픽 관리 시스템에 "신뢰 신호"로 브로드캐스트한다.
- how_combined: A(PID 튜닝의 기술적 실체—게인이 곧 응답 특성/예측 가능성을 결정한다는 사실)와 B(2026-07 운용 동향에 담긴 임무 맥락 변화, 규제·공역 협상 이슈)를 결합해, "제어 루프 파라미터 = 통신 프로토콜"이라는 제3의 층위를 만들었다. 기존에는 게인이 순수 내부 튜닝 대상이었고, 임무 맥락은 경로계획·스케줄링 층에서만 다뤄졌다.
- why_not_before: 제어공학 커뮤니티는 게인을 "성능 지표"로만 보고, 운용/규제 커뮤니티는 게인 값 자체를 볼 일이 없었다(그건 벤더 내부 튜닝 파일이지 공개 데이터가 아니었다). 두 영역이 서로 다른 조직·다른 데이터 포맷을 다뤘기 때문에 "게인이 신호가 될 수 있다"는 발상이 나올 접점 자체가 없었다.

## 후보 2
- idea: 뉴스·사고보고서·규제 동향 텍스트(B)를 그대로 오토튠 시뮬레이터의 "적대적 시나리오 생성기" 입력으로 쓰는 에이전트를 만든다. 즉 실제 세계에서 보도된 사건(예: 도심 협곡 GPS 음영, 스펙트럼 혼잡, 특정 지역 돌풍 사고)을 LLM이 물리 시뮬레이션 파라미터로 자동 번역해 PID 오토튠 루프에 지속적으로 주입하고, 게인은 "물리 방정식"이 아니라 "이번 주 뉴스 피드"에 의해 재학습된다.
- how_combined: A의 오토튠 메커니즘(시뮬레이션 기반 게인 최적화)과 B의 임무/뉴스 스트림(실제 발생한 운용 이슈의 텍스트 기록)을 결합해, 시뮬레이션 시나리오 생성 자체를 뉴스 파이프라인이 대체하도록 만들었다. 기존 오토튠은 물리 모델 기반 랜덤/그리드 탐색이었고, 뉴스는 사후 분석 리포트로만 소비됐다.
- why_not_before: 오토튠은 항공역학·제어이론 엔지니어의 영역이고 뉴스/사고 동향 분석은 운항관리·정책 담당자의 영역이라, 비정형 텍스트를 제어 시뮬레이션 파라미터로 자동 번역하는 LLM 계층이 최근까지 실용적이지 않았다. 두 데이터 형식(텍스트 서사 vs. 수치 시뮬레이션 입력) 사이의 자동 변환 기술이 성숙한 것이 최근이라 시도할 도구가 없었다.

## 다음 질문
- 게인 프로파일이 신뢰 신호로, 뉴스 기반 시나리오가 튜닝 입력으로 쓰이는 세상에서, 누군가 가짜 "예측 가능한" 게인 패턴을 흉내 내거나 조작된 뉴스/사고 리포트를 주입해 상대 드론이나 관제 시스템을 오도하는 "제어 루프 스푸핑" 공격이 가능해지는가 — 그리고 그런 조작을 걸러낼 인증·출처 검증 메커니즘은 어떤 형태여야 하는가?
