# Novel Combination 후보

## 후보 1
- idea: MAVLink 2 텔레메트리 패킷에 "이 필드값의 출처 신뢰도 등급"을 실시간으로 임베드하는 프로토콜 확장. 온보드 센서 직접 측정값, 다른 드론이 중계한 값, 지상국이 추정·보간한 값을 스웜 내에서 구분해, 수신 측 자율 판단 로직이 "이 데이터를 얼마나 믿고 반응할지"를 메시지 자체에서 읽을 수 있게 한다.
- how_combined: MAVLink 2의 메시지 서명·인증 계층("이 메시지는 위조되지 않았다")에, 세컨드 브레인 연구 워크플로의 evidence_tier 개념("이 주장은 1차 출처인가 추정인가")을 이식했다. 지금까지 MAVLink 보안은 "무결성/인증"만 다뤘고 "인식론적 신뢰도"는 다룬 적이 없다.
- why_not_before: 통신 프로토콜 보안 엔지니어링은 암호학적 신뢰(서명, 키 교환)를 다루는 영역이고, evidence_tier 같은 인식론적 신뢰 등급 체계는 연구 방법론 영역이라 서로 다른 커뮤니티에서 독립적으로 발전해왔다. "메시지가 안 변조됐다"와 "메시지 내용을 믿을 만하다"가 서로 다른 축이라는 인식 자체가 실시간 제어 프로토콜 설계에는 잘 반영되지 않았다.

## 후보 2
- idea: 세컨드 브레인의 재귀 창작 체인 구조(개체 A/B를 반복적으로 교차 결합해 발산적으로 새 조합을 생성하는 루프)를 그대로, MAVLink 메시지 타입·필드·타이밍 조합에 적용해 "아직 아무도 조합해보지 않은 프로토콜 상태"를 발산적으로 탐색하는 창작 에이전트를 만든다.
- how_combined: 이 Innovation Engine 자체의 메타 구조(라운드마다 이전 제안을 다른 방향으로 밀어붙이는 방식)를 "새 드론 아이디어 생성"이 아니라 "MAVLink 메시지 시퀀스의 미탐색 조합 생성"에 재적용했다. 대상만 바뀌었을 뿐 엔진 구조는 동일하다.
- why_not_before: 프로토콜 보안 연구는 전통적으로 퍼징(무작위 입력 변형)이나 알려진 CVE 패턴 재적용 방식이었고, "재귀적 발산 창작"이라는 연구 워크플로 메타패턴을 보안 취약점 탐색 도메인에 그대로 이식하는 발상은, 두 분야가 쓰는 도구와 용어 체계가 완전히 달라 접점이 드물었다.

## 다음 질문
후보 2의 창작 에이전트가 "아직 보고되지 않은 취약점 패턴"을 생성했을 때, 그것이 진짜 위협인지 LLM의 환각인지를 후보 1의 evidence_tier 체계로 자체 검증할 수 있는가 — 즉 AI가 스스로 만든 가설을 스스로 신뢰도 등급 매기는 폐루프가 성립할 수 있는가, 아니면 이런 자기참조적 검증은 항상 외부 실증(실제 하드웨어 재현)이 있어야만 유효한가?
