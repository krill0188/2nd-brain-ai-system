# Critique

## 채택 후보
- selected: 후보 1 — "지리서명 이력"은 검색 결과에서 직접적 유사 사례를 찾지 못했고, 후보 2는 이미 알려진 "위치 기반 파라미터 자동 조정"(예: 지오펜스 기반 고도 제한류) 개념과 겹칠 위험이 커서 상대적으로 신규성이 약함.

## Novelty
- score: 7
- rationale: 검색 결과에서 `geocomm` 항목은 일관되게 "DFR Routing(응급 출동 경로 계획, 완전한 위치 정보 제공)"이라는 운용 단계 기능으로만 등장하며(`entities/geocomm.md`, `concepts/drone-first-responder-dfr.md`), 파라미터 설정 이벤트에 규제적·지리적 근거를 서명해 남기는 감사 이력 개념은 어디에도 나타나지 않는다. `pixhawk`/`ardupilot`/`px4` 관련 raw 자료(`raw/articles/entity-pixhawk-hardware.md`, `raw/articles/entity-ardupilot.md`)도 파라미터를 정적 기본값 표(`ATC_RAT_RLL_P` 등)로만 다루고, 설정 행위 자체의 출처·컨텍스트 감사는 다루지 않는다. 다만 "지리서명"이라는 구체적 메커니즘(암호서명 + 지리좌표 + 규제 메타데이터 결합)이 다른 도메인(예: 문서 서명, 블록체인 위치증명)에서는 흔한 패턴이라 완전한 백지 발명은 아니라고 보아 10점보다는 낮게 준다.
- duplicate_of: 없음

## Feasibility
- score: 7
- rationale: GCS(지상국) 소프트웨어에서 파라미터 설정 시점의 GPS 좌표를 기록하는 것, 표준 PKI로 레코드에 서명하는 것, 미션 존 메타데이터(규제 구역 정보)를 별도 데이터로 결합하는 것은 모두 현재 존재하는 기술이며 새 하드웨어가 필요 없다. Pixhawk/ArduPilot/PX4는 이미 파라미터 값 자체를 로깅·버전관리하는 인프라(파라미터 파일, dataflash 로그)를 갖추고 있어 여기에 서명·지리컨텍스트 필드를 추가하는 확장은 현실적이다.
- missing_pieces: "미션 구역별 규제 근거"를 표준화된 스키마로 GeoComm류 시스템과 연동해 조회하는 기존 API·데이터셋은 검색 결과에 확인되지 않음. 즉 지리좌표→규제근거 매핑을 자동화할 신뢰 가능한 소스가 실제로 존재하는지는 검증되지 않았고, 이 부분이 구현 시 병목이 될 수 있음.
